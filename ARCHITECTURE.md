## Обзор

Узел — долгоживущий процесс на Python 3.11+, использующий `asyncio`. Внешние
связи — TCP. Поверх транспорта работают подсистемы: идентичность, DHT,
туннели, прикладные сервисы, метрики. Все подсистемы взаимодействуют через
явные интерфейсы; прикладной слой не имеет прямого доступа к k-bucket и
локальному хранилищу DHT.

## Подсистемы

| Подсистема | Назначение | Статус |
|---|---|---|
| Transport | TCP, кадрирование, тайм-ауты, сериализация | реализовано |
| Identity and Security | долговременная идентичность, handshake, ключи, replay-защита | план |
| DHT and Discovery | k-bucket, bootstrap, RPC, lookup, хранение записей | план |
| Tunnel Management | построение, состояние, передача, контроль, перестроение | план |
| Application Services | текстовые сообщения | план |
| Metrics and Experimentation | события, метрики, сценарии, экспорт | план |
| User Interface | консольный интерфейс | частично (serve, ping-peer) |

## Границы модулей

- `transport.frame` — чистые структуры и ошибки, без I/O.
- `transport.codec` — сериализация payload.
- `transport.tcp` — asyncio-сервер, клиент, потоковый декодер.
- `config` — dataclass-конфиг и загрузка TOML.
- `cli` и `__main__` — точка входа.

Транспорт не знает о DHT, идентичности и туннелях. Всё вышележащее
использует `Connection.send()`, `Connection.request()` и колбэк `on_frame`.

## Транспорт

TCP предоставляет поток байтов и не сохраняет границы прикладных сообщений,
поэтому реализовано собственное кадрирование. Заголовок — 24 байта:
`version(1) + type(1) + flags(2) + request_id(16) + payload_length(4)`.
`MAX_FRAME_PAYLOAD = 65536`. Значение длины проверяется до выделения буфера.

Потоковый декодер `StreamDecoder` корректно обрабатывает частичный заголовок,
частичный payload, несколько кадров в одном чтении и разрыв внутри кадра.

## Публичный фасад узла

Планируемый фасад (появится по мере реализации подсистем):

```text
join(bootstrap_peers)
lookup_node(target_node_id)
put_record(key, signed_record, ttl)
get_record(key)
build_tunnel(destination_node_id, constraints)
send_via_tunnel(tunnel_id, payload)
close_tunnel(tunnel_id)
get_network_state()
```

## Статус реализации

- Этап 0/1: каркас, транспорт, кадрирование, `serve`, `ping-peer`.
- Этап 2: идентичность, k-bucket, `PING`/`FIND_NODE`, итеративный lookup.
- Этап 3: `STORE`/`FIND_VALUE`, подписи, TTL, репликация.
- Этап 4: защищённая сессия, negative-тесты.
- Этап 5: туннель и прикладные сообщения.
- Этап 6: масштабирование и сценарии отказов.
- Этап 7: документация и эксперимент.
